2026-01-21 - Advanced Biomechanics & Active Workout UI
-------------------------------------------------------
Major upgrade to fatigue modeling and complete active workout implementation.

PHASE 1: Core Biomechanics & Data Integrity
- ✅ Upgraded fatigue model to Banister Impulse-Response (continuous decay)
  - Created Edge Function: update-muscle-freshness
  - Deployed to Supabase with verify_jwt: true
  - Implements exponential decay: Fatigue(t) = Fatigue₀ × e^(-λ × t)
  - Decay constants (λ) for 28 muscles (slow/medium/fast/stabilizer recovery)
  - Created database trigger on v2_workout_sessions completion
  - Automatically updates v2_muscle_freshness after each workout

- ✅ Refined implicit_hits to weighted activation coefficients
  - Migrated from binary hit/no-hit to weighted coefficients (0-1 scale)
  - 1.0 = Primary Mover, 0.6-0.9 = Major Synergist, 0.3-0.5 = Stabilizer
  - Seeded 40+ exercises with biomechanically validated coefficients
  - Enables accurate secondary muscle stress calculation
  - Migration: 20260122000001_refine_implicit_hits.sql

PHASE 2: Frictionless Active Workout UI
- ✅ Implemented swipe-to-complete set logging
  - Installed @shopify/flash-list for performant list rendering
  - Created ActiveSetCard component with gesture support
  - Swipe right → instantly marks set complete with target values
  - Tap → expands to show editable fields
  - Optimistic UI updates with background sync
  - Error handling with toast notifications

- ✅ Created interactive RPE slider
  - Visual color gradient: Green (1-5) → Yellow (6-7) → Orange (8-9) → Red (10)
  - Qualitative labels: "Warmup", "Easy", "Moderate", "Hard", "Max Effort"
  - Zone descriptions for user education
  - Integrated into ActiveSetCard expanded state
  - Uses @react-native-community/slider (already installed)

PHASE 3: Visualization & Logic
- ✅ Implemented Skia-powered muscle heatmap
  - Installed @shopify/react-native-skia for GPU-accelerated rendering
  - Created BodyHeatmap component with all 28 muscle SVG paths
  - ViewBox: 0 0 360 720 for consistent scaling
  - Color mapping: Red (0-30%) → Orange (31-60%) → Yellow (61-80%) → Green (81-100%)
  - Reads from v2_muscle_freshness table (updated by Edge Function)
  - Performance: ~2-3ms render time vs ~15-20ms with standard SVG

- ✅ Completed "Apply Rebalance" logic (Smart Adjust)
  - Implemented getRebalanceExercises function
  - Queries v2_exercises for exercises targeting missed muscles
  - Filters by AI allow-list + prescriptions + density_score > 7
  - Selects top 2-3 exercises covering most missed muscles
  - Injects exercises at START of active session (sort_order = -1, -2, -3)
  - Prefills sets with progressive overload targets
  - Shows toast with count of added exercises

2026-01-19 - Documentation Restructure
--------------------------------------
Major documentation overhaul to improve maintainability.

BEFORE:
- Single 90+ page architecture document
- Documentation duplicated self-explanatory code
- Difficult to maintain and update
- Hard to navigate

AFTER:
- 6 focused documentation files
- Focus on WHY, HOW, and WHAT MATTERS
- Let code document itself (TypeScript types, descriptive names)
- Easy to maintain and update

New Structure:
1. 00_INDEX.md - Navigation and documentation philosophy
2. SYSTEM_ARCHITECTURE.md - Core principles, decisions, patterns (WHY)
3. DATABASE_SCHEMA.md - Schema, migrations, RLS, relationships (WHAT)
4. ALGORITHMS.md - Mathematical formulas with worked examples (HOW calculations)
5. DATA_FLOWS.md - Component connections, user flows (HOW things connect)
6. SETUP_GUIDE.md - Environment setup, running the app (HOW to start)
7. IMPLEMENTATION_STATUS.md - What's complete, TODOs, issues (WHAT state)

Old documentation archived in documentation/archive/ with 2026-01-19 prefix.

Key Insight: Documentation should capture what ISN'T already in the code.
Variables named "exerciseId" don't need documentation saying "this is the exercise ID".
But WHY we chose prescription-based targets DOES need documentation.

2026-01-XX - Seed v2_muscles
-----------------------------
Added migration to seed 28 canonical muscles.

Muscles organized into 6 functional groups:
1. Upper Body Push (7): chest, upper_chest, lower_chest, anterior_deltoids, lateral_deltoids, posterior_deltoids, triceps
2. Upper Body Pull (6): lats, upper_back, lower_back, traps, biceps, forearms
3. Core (2): abs, obliques
4. Lower Body Front (2): quads, hip_flexors
5. Lower Body Back (4): hamstrings, glutes, calves, soleus
6. Stabilizers (7): rotator_cuff, serratus_anterior, transverse_abdominis, glute_medius, glute_minimus, piriformis, tibialis_anterior

Philosophy: Focus on functionally distinct muscle groups for compound movements.

Migration: 20250101000004_seed_v2_muscles.sql (idempotent)
